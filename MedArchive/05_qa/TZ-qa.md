# ТЗ: QA (роль: AI-агент QA)

Цель: доказать, что «Медархив» выполняет требования задания R1 до R7 и правила брендбука, и не выпустить сборку с дефектом P0.

## 1. Входные документы

`05_qa/test-strategy.md` (пирамида, окружения, критерии выпуска), `05_qa/test-cases.md` (78 проверок, из них 46 P0 обязательны; TC-104 вне объёма прототипа вместе с AI, ADR-042), `01_common/06-api-contract.md` (каталог ошибок), `01_common/04-customer-journey.md` (тексты интерфейса), `02_design/brandbook.pdf` (визуальные правила, чек-лист доступности на странице 24).

## 2. Задачи

| ID | Задача | Критерий готовности |
|---|---|---|
| QA-01 | Фикстуры: 6 PDF из задания + сгенерированные `big-21mb.pdf`, `fake.pdf`, `encrypted.pdf`, `broken.pdf`, `cyrillic «имя» файла.pdf` | Скрипт `make fixtures`, файлы не коммитятся, кроме шести исходных |
| QA-02 | API-тесты по контракту: schemathesis на `openapi.yaml` + ручные TC-022, 023, 043, 058, 059, 090, 093, 094, 097, 098 | Зелёные в CI, отчёт JUnit |
| QA-03 | DB-тесты изоляции TC-091, 092, 096, 096b, 099 на Testcontainers | Зелёные |
| QA-04 | E2E Playwright: все P0 из разделов 1 до 7 на Chromium десктоп и WebKit мобильный | Зелёные три прогона подряд (нет флаки) |
| QA-05 | Доступность: axe-core TC-110, клавиатура TC-111 | 0 serious и critical |
| QA-06 | Визуальная регрессия TC-115 против эталонов приложения; снимки `02_design/screens` служат образцом для ручной сверки | Порог 0,1% |
| QA-07 | Ручной чек-лист 30 минут (`test-strategy.md`, раздел 5) на локальной сборке `docker compose` (ADR-040) | Протокол с временем и результатом каждого шага |
| QA-08 | Отчёт о выпуске | Таблица P0 / P1 / P2: прошло, упало, ссылка на дефект |

## 3. Правила

| Правило | Почему |
|---|---|
| Время зафиксировано (`page.clock`, `freezegun`) | Даты «сегодня» и границы суток детерминированы |
| Каждый E2E создаёт свой архив | Тесты не зависят друг от друга, параллельны |
| Сеть ломаем через `page.route`, а не `sleep` | Воспроизводимо |
| Дефект содержит шаги, ожидаемое, фактическое, `request_id` | Бэкенд находит запрос в логах |
| Тексты сверяются с каталогом ошибок дословно | Тексты интерфейса это часть контракта |

## 4. Критерии выпуска

Все P0 зелёные; P1 открытых не больше 3 и ни одного в разделах 6 и 7; axe 0 serious; сценарий из задания (загрузить 6 PDF, найти, отфильтровать по дате, открыть, добавить заметку, переоткрыть браузер) пройден вручную на локальной сборке `docker compose` (ADR-040).
