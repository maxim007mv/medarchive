# Стратегия тестирования: Медархив

Цель: каждое требование задания (R1..R8) закрыто автоматическим тестом, который падает, если требование нарушено. Ручная проверка остаётся только для того, что автоматизация не ловит: смысл текстов, ощущение анимаций, экранные дикторы.

## 1. Пирамида и бюджет времени CI

| Уровень | Инструмент | Что проверяет | Где | Время в CI |
|---|---|---|---|---|
| Unit (бэк) | pytest | правила раздела 3 `TZ-backend.md`, имена файлов экспорта, нормализация ключа, курсор | `apps/api/tests/unit` | < 30 с |
| Unit (фронт) | Vitest | `lib/format.ts`, `lib/filters.ts`, валидация дат, имя по умолчанию, склонения | `apps/web/**/*.test.ts` | < 20 с |
| Компонентные | Vitest + Testing Library | состояния Button, DateInput, SegmentedControl, DeleteDialog, NotePanel | `apps/web/components` | < 60 с |
| Интеграционные | pytest + testcontainers (PostgreSQL 17 и 18, MinIO) | API целиком с реальной БД и S3: загрузка, фильтры, удаление с ошибкой S3, экспорт | `apps/api/tests/integration` | < 3 мин |
| Контрактные (каскадные) | schemathesis по `openapi.yaml`; генерация клиента + `tsc` | бэк соответствует схеме; фронт компилируется против схемы; изменение схемы ломает обе стороны сразу | CI job `contract` | < 3 мин |
| E2E | Playwright (Chromium, Firefox, WebKit; мобильный профиль iPhone 13) | путь пользователя этапы 0..6 | `e2e/` | < 8 мин |
| Регрессионные | весь e2e-набор + набор багов `@regression` | ничего не сломалось после изменения | каждый PR в main | входит в E2E |
| Визуальные | Playwright `toHaveScreenshot`, порог `maxDiffPixelRatio: 0.001` | 25 экранов из `02_design/screens.md` x 2 темы x 2 ширины | `e2e/visual` | < 4 мин |
| Доступность | @axe-core/playwright на каждом экране + ручной чек-лист | WCAG 2.2 AA | `e2e/a11y` | < 2 мин |
| Производительность | Lighthouse CI, бюджет бандла | LCP < 2,0 с, JS < 180 КБ gzip, CLS < 0,05 | CI job `perf` | < 3 мин |
| Нагрузочные | k6 | p95 и отсутствие 5xx под нагрузкой, 429 вместо падения | ночной job на staging | 15 мин |
| Безопасность | ZAP baseline, `pip-audit`, `pnpm audit`, тесты изоляции пространств | | ночной job | 10 мин |

## 2. Каскадные проверки контракта
1. `openapi.yaml` меняется только PR-ом, в котором одновременно: миграция (если нужно), код бэка, перегенерированный клиент фронта.
2. Job `contract`: (а) `schemathesis run openapi.yaml --checks all --base-url $API`; (б) сравнение `app.openapi()` с файлом (`openapi-diff`, breaking = красный); (в) `pnpm gen:api && pnpm tsc --noEmit`.
3. Если (а) зелёный, а (в) красный, значит фронт использует поле, которого нет: падение без запуска e2e экономит 8 минут.

## 3. Данные для тестов
Фикстуры: `05_qa/fixtures/*.pdf` (6 файлов из задания). Сид для e2e создаёт ровно эти 6 документов:

| Файл | Название | Тип | Дата документа |
|---|---|---|---|
| 01 | Общий анализ крови | Анализ | 08.04.2026 |
| 02 | Биохимический анализ крови | Анализ | 08.04.2026 |
| 03 | Липидограмма | Анализ | 21.05.2026 |
| 04 | Заключение терапевта | Заключение | 10.04.2026 |
| 05 | УЗИ почек и мочевого пузыря | Заключение | 22.05.2026 |
| 06 | ЭКГ покоя | Заключение | не указана |

Дополнительно генерируются: `big-21mb.pdf`, `fake.pdf` (PNG с расширением .pdf), `encrypted.pdf`, `broken.pdf` (обрезан на середине), `cyrillic «имя» файла.pdf`.

Время в тестах фиксируется (`page.clock`, `freezegun`): «сейчас» = 10.11.2026 12:00 МСК, кроме тестов на границы суток.

## 4. Окружения и запуск
`make test` (unit + интеграционные), `make e2e` (поднимает compose, сид, Playwright), `make load` (k6 против staging). Отчёты: JUnit для CI, HTML Playwright с трассами при падении, k6 summary в артефактах.

## 5. Ручной чек-лист перед сдачей (30 минут)
1. Клавиатура: весь путь этапов 0..5 без мыши; видимый фокус везде.
2. VoiceOver (Safari) и NVDA (Firefox): список читается как таблица, «Сохранено» объявляется, ошибки формы объявляются.
3. Зум 200% и ширина 320 px: нет горизонтальной прокрутки, кроме таблицы.
4. `prefers-reduced-motion: reduce`: шиммер и подсветка строк отключены.
5. iPhone с вырезом: закреплённая кнопка и нижние листы не заходят под индикатор «Домой».
6. Тексты: нет английских слов, нет длинного тире, даты в формате дд.мм.гггг.

## 6. Критерии выпуска
Все уровни таблицы 1 зелёные; 0 открытых дефектов классов К1 и К2; ручной чек-лист пройден; данные сохраняются после перезапуска (TC-080, TC-081).

Классы дефектов: К1 потеря данных или чужие данные (критичный); К2 требование R1..R8 не выполняется (серьёзный); К3 состояние или текст не по макету; К4 косметика.
