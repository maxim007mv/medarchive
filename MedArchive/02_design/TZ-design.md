# ТЗ: дизайн (роль: AI-агент дизайна)

Цель: поддерживать дизайн-систему «Медархив» и макеты так, чтобы фронтенд собирал экраны без догадок. Эталон: `02_design/brandbook.pdf` (33 страницы, A4 альбом) и `02_design/brandbook.md`.

## 1. Входные документы

| Документ | Что брать |
|---|---|
| `02_design/brandbook.pdf`, `brandbook.md` | Правила, токены, компоненты, состояния, «правильно / неправильно» |
| `02_design/tokens.json`, `tokens.css` | Единственный источник значений цвета, отступов, радиусов, движения |
| `01_common/04-customer-journey.md` | Все шаги и состояния пользователя |
| `01_common/11-design-rationale.md` | Почему каждый экран и действие устроены так |
| Figma-файл (ссылка в `00_START_HERE/README.md`) | Экраны десктоп 1440 x 900 и мобильный 390 x 844, светлая и тёмная тема |

## 2. Задачи

| ID | Задача | Критерий готовности |
|---|---|---|
| DS-01 | Перенести токены в Figma Variables: цвета (на Starter две коллекции `color · light` и `color · dark` с одинаковыми именами переменных, на платном тарифе одна `color` с режимами light и dark), `space`, `radius`, `size` | Каждый цвет в макетах привязан к переменной, ни одного «сырого» hex |
| DS-02 | Компоненты с вариантами: Button (p, s, t, dg, dgt x default, hover, focus, loading, disabled x sm, md, lg), Input, Segment, Radio row, Checkbox, Tag, Chip, Toast, Alert, Banner, Modal, Sheet, List row, Mobile card, Skeleton | Все состояния из брендбука, страницы 13 до 23 |
| DS-03 | Экраны D01 до D14 и M01 до M08 в обеих темах из компонентов (44 экрана); D15, D16 вне объёма (ADR-042), снимками в секции «Вне объёма: AI» | Совпадают со снимками `02_design/screens` (`screens.md`); нет отсоединённых экземпляров |
| DS-04 | Аннотации для разработки: отступы, цели нажатия, порядок фокуса, aria-label иконок-кнопок | На каждом экране скрытый слой `Spec` |
| DS-05 | Проверка контраста всех новых пар по WCAG 2.2 AA (текст 4,5:1, границы и крупный текст 3:1) | Таблица в `brandbook.md`, раздел 1.3, дополнена |
| DS-06 | Пересборка PDF брендбука по `02_design/source/README.md` (`contrast.py`, `bb.py`, `pdf.py` через Playwright) | 0 переполнений в выводе `overflow []`, шрифт Medeo встроен (`pdffonts`) |

## 3. Правила (кратко, полностью в брендбуке)

| Правило | Источник |
|---|---|
| Одна главная кнопка на экран: `#171717`, радиус 12; в тёмной теме `#F4F4F5` | S11 |
| Disabled `#EBEBED` с текстом `#71717A` и причиной рядом; не похож на активный сегмент | S7 |
| Сетка 8 px, закон близости: 8 внутри группы, 16 между полями, 24 до 32 между блоками | S10 |
| 2 до 4 варианта: сегмент или радио-строки; 5 и больше: список с поиском | S8 |
| Вся строка кликабельна, цели нажатия от 40 px, мобильные главные 48 px | S10 |
| Модалка только для необратимого и короткой формы; заголовок «глагол + объект?», «Отмена» слева в фокусе | S1, S2 |
| Мобильный нижний лист с `env(safe-area-inset-bottom)` | S13 |
| Скелетон 1 до 10 с ожидания, AI-шиммер бирюзовый внутри полей | S5, S6 |
| Шрифт Medeo Sans и Mono (OFL 1.1), даты моноширинным | S15 |

## 4. Чего не делать

Не вводить новый акцентный цвет; не использовать бежевые и цветные подложки; не прятать применённые фильтры в счётчик; не делать иконку единственной целью нажатия в строке; не использовать слово «Вы уверены?».

## 5. Определение готовности

Макеты в Figma на трёх страницах «Основа» (переменные и компоненты), «Десктоп», «Мобайл» (тариф Starter: не больше 3 страниц и 1 режим на коллекцию, поэтому темы двумя коллекциями `color · light` и `color · dark`); стили текста на Geist до замены семейства на Medeo в Figma desktop; PDF пересобран; QA-агент подтвердил соответствие чек-листу доступности (брендбук, страница 25).
