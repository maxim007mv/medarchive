# Правила для AI-агентов (общие для всех ролей)

Этот файл кладётся в корень репозитория. Его читает каждый агент перед любой задачей.

## 1. Роли и входы

| Роль | Папка ТЗ | Главные входы |
|---|---|---|
| Дизайн | `02_design/TZ-design.md` | `brandbook.pdf`, `tokens.json`, `11-design-rationale.md` |
| Фронтенд | `03_frontend/TZ-frontend.md` | `openapi.yaml`, `tokens.css`, `04-customer-journey.md`, `screens/` |
| Бэкенд | `04_backend/TZ-backend.md` | `openapi.yaml`, `06-api-contract.md`, `05-architecture.md` |
| База данных | `04_backend/TZ-database.md` | `07-data-model.sql`, `07-database.md` |

| DevOps и безопасность | `07_devops_security/TZ-devops-security.md` | `08-security-privacy.md`, `05-architecture.md` |

## 2. Источники истины и приоритет

1. `01_common/openapi.yaml` для контракта API (при расхождении с текстом прав YAML).
2. `01_common/07-data-model.sql` для схемы.
3. `02_design/tokens.json` для значений дизайна.
4. `01_common/09-decisions-ADR.md` для решений: менять решение можно только новой записью ADR.
5. Тексты интерфейса: словарь `docs/texts.md` (ключи, правила оформления, каталог ошибок, совпадающий с `06-api-contract.md`, раздел 8).

## 3. Обязательные правила

| Правило | Почему |
|---|---|
| Пути API только `/api/v1/...` | Версионирование (ADR-020) |
| Ни одного значения ПДн (название, заметка, имя файла, текст PDF) в логах, ошибках, аналитике, тестовых снимках сетевого трафика | 152-ФЗ, ASVS V16 |
| Только инфраструктура в РФ (Yandex Cloud ru-central1; прототип сдаётся локально через `docker compose`, ADR-040); внешние CDN, шрифты, телеметрия запрещены | 152-ФЗ ст. 18 ч. 5 |
| Цвета и отступы только из токенов, без «сырых» hex | Две темы из одной разметки |
| Каждая задача закрывается тестом из `test-cases.md` или новым тестом с ID | Проверяемость |
| Коммит `FE-12: ...`, `BE-06: ...`, `DB-03: ...`, один ID на коммит | Трассировка задачи в код |
| Перед PR: lint, typecheck, unit, контрактный тест против `openapi.yaml` | CI быстрее ревью |
| Не придумывать новые эндпоинты, поля, тексты ошибок: сначала правка контракта | Контракт общий для ролей |
| Неясность фиксируется вопросом в PR, а не догадкой | Цена ошибки в медицинских данных |

## 4. Определение готовности задачи

Критерий приёмки из ТЗ выполнен; тест с ID зелёный; в коде нет TODO без ID задачи; документация обновлена, если поменялось поведение; для UI приложен снимок светлой и тёмной темы.
