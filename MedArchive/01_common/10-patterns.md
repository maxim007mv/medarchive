# 10. Каталог паттернов

Для каждого паттерна: где применяется, почему именно он, что отброшено, источник (S.. в `02-research-sources.md`).

## 1. Бэкенд

| Паттерн | Где | Почему | Отброшено | Источник |
|---|---|---|---|---|
| Модульный монолит | `api/modules/{auth,documents,uploads,suggestions,exports}` с явными публичными сервисами | Одна транзакция на создание документа, один деплой; границы модулей готовят выделение воркера без сетевых вызовов | Микросервисы | S25 |
| Слои router → service → repository | Каждый модуль | Маршрут знает HTTP, сервис бизнес-правила, репозиторий SQL; тесты сервиса без HTTP | Логика в маршрутах | S50 |
| Внедрение зависимостей FastAPI | `get_session`, `require_scope("documents:write")`, `get_db(workspace_id)` | Проверка сессии и скоупа декларативна и видна в OpenAPI; невозможно забыть на маршруте | Middleware с ручными проверками | S50 |
| Unit of Work на запрос | Транзакция SQLAlchemy открывается в зависимости, первая команда `set_config('app.workspace_id', ..., true)` | Контекст RLS живёт ровно транзакцию, безопасно в пуле | Настройка на соединение | S32 |
| Ресурс как процесс (upload → document) | `POST /uploads`, затем `POST /documents` | Тяжёлая передача вне API, атомарная фиксация метаданных и переноса файла | Один multipart | S45, S47 |
| Idempotency Key | Создающие POST | Повтор безопасен | Дедупликация по содержимому | S19 |
| Optimistic Concurrency (ETag) | PATCH, DELETE | Без блокировок, конфликт виден пользователю | Пессимистичная блокировка | S17, S24 |
| Keyset Pagination | Список | Стабильная стоимость | OFFSET | S39 |
| Envelope Encryption | Поля и файлы | Ключ данных рядом с данными только обёрнутым | Один ключ на всё | S44 |
| Blind Index | Поиск по названию | Поиск без открытого текста | Открытый pg_trgm | S33 |
| Soft Delete + Purge Job | Документы, архивы | Мгновенный ответ, гарантированное уничтожение | Только физическое удаление | S48 |
| Append-only Audit Log | `audit_log` | Подотчётность | Изменяемый журнал | S55 |
| Bounded Queue + Load Shedding | AI-подсказка, `arq` + Redis, глубина 20 | Явный 429 вместо общих таймаутов | Неограниченная очередь | S18, S20 |
| Timeout + Fallback | Вызов модели 8 с, фронт 10 с | Основной сценарий не зависит от AI | Ожидание без предела | S6 |
| Anti-corruption layer для LLM | `suggestions/adapter.py` нормализует ответ по JSON-схеме | Модель меняется без изменения домена; невалидный ответ отбрасывается | Прямое использование ответа | S27 (API10) |
| Problem Details | Обработчик исключений → `problem+json` | Единый формат ошибок | Разные форматы по маршрутам | S16 |
| Eager loading (`selectinload`), `lazy="raise"` | Репозитории | Нет N+1: ленивую загрузку в рантайме нельзя случайно вызвать | Ленивая загрузка | S40 |
| Streaming | Отдача PDF (Range) и ZIP экспорта | Постоянная память на любом размере | Сборка в памяти | S52 |
| Rate limiter GCRA | Redis | Ровное ограничение без всплесков на границе окна | Фиксированное окно | S20 |

## 2. Фронтенд

| Паттерн | Где | Почему | Отброшено | Источник |
|---|---|---|---|---|
| Server Components для каркаса + Client Components для интерактива | Страница списка: каркас и первая страница данных SSR, фильтры и таблица на клиенте | Быстрый первый экран и интерактивность | Чистый SPA | S54 |
| Состояние фильтров в URL (`nuqs`) | Поиск, тип, период, сортировка | Ссылка воспроизводима, «Назад» работает, перезагрузка не теряет фильтр | Состояние в памяти | S8 |
| Серверный кэш TanStack Query | Ключи `['documents', filters]`, `['document', id]` | Дедупликация, повтор, инвалидация | Ручной fetch + useState | S56 |
| Optimistic update с откатом | Заметка, переименование | Мгновенный отклик; при 412 откат и сообщение | Ожидание ответа | S56 |
| Debounced autosave | Заметка: 800 мс после ввода, индикатор «Сохраняем… / Сохранено» | Нет кнопки «Сохранить» для заметки, нет потери текста | Сохранение по blur | S7 |
| Генерированный клиент из OpenAPI | `openapi-typescript` + `openapi-fetch` | Типы запросов и ошибок совпадают с бэкендом | Ручные типы | S50 |
| Схемы форм zod из контракта | Форма документа | Одинаковые правила на клиенте и сервере | Дублирование правил | S50 |
| Composition компонентов (Radix + shadcn) | Dialog, Sheet, RadioGroup, Toast | Доступность из примитивов, стиль наш | Свои модалки | S53 |
| Responsive pattern: Dialog на десктопе, Sheet на мобильном | Форма, удаление, экспорт, фильтр | Один компонент `ResponsiveDialog`, разная подача | Две реализации | S1 |
| Design tokens как CSS-переменные | `tokens.css`, `data-theme` на `html` | Одна разметка, две темы, без перерисовки | Классы на каждый цвет | S11 |
| Skeleton + Suspense | Список, карточка | Структура видна во время ожидания | Спиннер на весь экран | S5 |
| Error boundary + повтор | Список, панель документа | Сбой одного блока не ломает страницу | Белый экран | S7 |
| Progressive disclosure | «Ещё» в строке, подсказка про документ без даты по ссылке | Меньше шума, всё доступно | Все действия видны всегда | S3 |
| Upload state machine | `idle → selected → uploading(p) → verifying → ready → saving → saved`, ветки `failed(code)` | Каждое состояние имеет экран (04-customer-journey) | Флаги `isLoading` | S7 |
