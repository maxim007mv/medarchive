# 03. Выбор стека (ADR-001)

Статус: принято. Дата: 10.11.2026.

## 1. Решение одной строкой

**Next.js 15 (App Router, TypeScript) + Tailwind CSS 4 + Radix UI на фронте, FastAPI (Python 3.12) + PostgreSQL 17/18 + S3-совместимое хранилище на бэке, docker compose локально и только Yandex Cloud ru-central1 онлайн (152-ФЗ ст. 18 ч. 5, S42): Managed PostgreSQL, Object Storage, KMS, Lockbox.**

## 2. Ограничения, из которых выбираем

| Ограничение | Источник | Что это значит для стека |
|---|---|---|
| Работающий прототип, проверка «от начала до конца» | Задание | Меньше движущихся частей, предсказуемый деплой |
| Сохранение PDF и данных после повторного открытия | Задание, R7 | Серверное хранение файлов и метаданных (см. 02, раздел 4) |
| Обязательная разработка с AI-агентами | Задание | Популярные, хорошо типизированные фреймворки: агенты пишут их код точнее |
| Онлайн-ссылка или локальный запуск по инструкции | Задание | Один `docker compose up` + один деплой-скрипт |
| Расширяемость под AI (подсказка полей, позже OCR) | Наше предложение | Python-экосистема для PDF и LLM |
| Медицинские данные | 152-ФЗ, специальная категория ПДн | Шифрование, минимум сторонних сервисов, возможность хостинга в РФ |

## 3. Бэкенд: Python (FastAPI) против Go

| Критерий | FastAPI (Python 3.12) | Go 1.23 (chi / net/http) | Вес | Комментарий |
|---|---|---|---|---|
| Скорость разработки CRUD + загрузки | Высокая: Pydantic-модели = валидация + OpenAPI | Средняя: ручная валидация или кодогенерация | 3 | Для 12 эндпоинтов Python быстрее на 30 до 40% по нашей оценке |
| Контракт API | OpenAPI генерируется из кода автоматически | Нужен oapi-codegen или swag | 3 | Контракт питает генерацию TS-клиента и контрактные тесты |
| Работа с PDF | pypdf: проверка сигнатуры, число страниц, текстовый слой | pdfcpu, меньше примеров | 2 | Нужно для валидации и AI-подсказки |
| AI / LLM | Официальные SDK, httpx, очереди, токенайзеры | SDK есть, экосистема уже | 2 | Опциональная функция, но в планах |
| Производительность | Достаточна: uvicorn, async, тысячи RPS на I/O | Выше в 3 до 10 раз | 1 | Нагрузка прототипа: единицы RPS. Узкое место это сеть и S3, не CPU |
| Потоковая выдача ZIP | `StreamingResponse` + zipstream | `archive/zip` в стандартной библиотеке | 1 | Оба хороши |
| Размер и холодный старт контейнера | 120 до 180 МБ, старт 1 до 2 с | 15 до 25 МБ, старт < 100 мс | 1 | Важно для serverless, у нас постоянный контейнер |
| Качество кода от AI-агентов | Очень высокое, огромный корпус примеров | Высокое | 2 | Задание оценивает в том числе работу с AI |
| **Итог (взвешенно)** | **Выбран** | Резерв | | Go оправдан, если появится высоконагруженный сервис (конвертация, OCR-воркер на тысячи файлов) |

Почему не «только Next.js без бэкенда» (Route Handlers + Supabase SDK напрямую): отброшено. (а) Бизнес-логика расползается между клиентом и RLS-политиками, (б) регионы Supabase вне РФ, а хранение ПДн граждан РФ требует баз данных на территории РФ (152-ФЗ ст. 18 ч. 5, S42; ADR-007), (в) контрактные и интеграционные тесты сложнее. Запасного варианта на чужой инфраструктуре нет: при нехватке времени упрощаем функциональность (AI-подсказка выключена флагом), а не меняем место хранения.

## 4. Фронтенд

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Next.js 15 App Router** | SSR первой страницы, роутинг, `next/font` подключает Medeo из npm, деплой одним контейнером | Порог входа в Server Components | **Выбран** |
| Vite + React SPA | Проще, быстрее сборка | Нет SSR, роутинг и деплой собираем сами | Резерв |
| SvelteKit | Мало кода | Меньше компонентов с доступностью, агенты пишут хуже | Нет |

Библиотеки фронта:

| Задача | Библиотека | Почему |
|---|---|---|
| Примитивы с доступностью (Dialog, RadioGroup, Popover, Toast) | Radix UI через shadcn/ui | Фокус-ловушка, Esc, aria из коробки; shadcn по умолчанию даёт чёрную главную кнопку, что совпадает с брендбуком |
| Стили | Tailwind CSS 4 + CSS-переменные из `02_design/tokens.css` | Токены одни для двух тем |
| Данные с сервера | TanStack Query 5 | Кэш, повторы, оптимистичные обновления заметки |
| Формы | react-hook-form + zod (схемы генерируются из OpenAPI) | Одна схема валидации на клиенте и сервере |
| Состояние фильтров | `nuqs` (состояние в URL) | Ссылка с фильтром воспроизводима, «Назад» работает |
| Даты | date-fns, `ru` locale | Лёгкая, tree-shaking |
| Просмотр PDF | Встроенный просмотрщик браузера через `<iframe src=…#view=FitH>` + fallback-ссылка; pdf.js только если нужен единый вид | Ноль зависимостей, нативный поиск и печать |
| Иконки | lucide-react | Единый штрих 1,75 px |
| Шрифт | `medeo-font` (npm, OFL 1.1) | См. брендбук, раздел «Типографика» |

## 5. Данные и хранение

| Слой | Выбор | Альтернатива | Почему |
|---|---|---|---|
| Метаданные | PostgreSQL 17 (проверено на 18) | SQLite | Транзакции, `pg_trgm` для поиска по подстроке, управляемые инстансы везде |
| Файлы | S3-совместимое хранилище: MinIO локально, Yandex Object Storage онлайн | Файлы в БД (bytea) | Дёшево, presigned URL, не раздувает бэкапы БД |
| Миграции | Alembic | Ручной SQL | Версионирование схемы |
| ORM | SQLAlchemy 2.0 async | Tortoise, raw SQL | Зрелость, типизация |
| Кэш и очередь (только для AI) | Redis 7 (arq) | Celery | Лёгкий async-воркер, ограниченная очередь для backpressure |

## 6. AI-интеграция (опциональная, за флагом `AI_SUGGEST_ENABLED`)

| Вопрос | Решение |
|---|---|
| Что делает | По текстовому слою PDF предлагает название, тип и дату документа. Пользователь подтверждает или правит. Медицинских выводов нет |
| Модель | Любой OpenAI-совместимый endpoint. Для данных граждан РФ рекомендуем YandexGPT или GigaChat с хостингом в РФ; для теста допустима любая модель на синтетических PDF |
| Вход | Первые 4000 символов текста страницы 1 без ФИО: перед отправкой ФИО и дата рождения маскируются регулярными выражениями |
| Выход | Строгий JSON по схеме `{title, type, document_date, date_evidence}`; невалидный ответ = подсказки нет, форма остаётся ручной |
| Нагрузка | Ограниченная очередь + 429 с `Retry-After` (см. 05-architecture, раздел 7) |
| Почему не обязательная часть | Задание прямо говорит, что распознавание не требуется. Функция показывает AI-навык, но не может сломать основной сценарий |

## 7. Инфраструктура и деплой

| Окружение | Как | Где хранятся документы |
|---|---|---|
| Локально | `docker compose up` поднимает web (3000), api (8000), postgres (5432), minio (9000/9001) | Docker-тома `pg_data`, `minio_data` на диске компьютера |
| Онлайн | Yandex Cloud ru-central1: Serverless Containers (web, api) + Managed PostgreSQL + Object Storage + KMS | Только РФ; поля и файлы зашифрованы на уровне приложения (08-security, раздел 5) |
| Vercel / Fly.io / Neon / Supabase | Отброшены: регионы вне РФ (152-ФЗ ст. 18 ч. 5, ADR-007) | |

CI: GitHub Actions: lint, typecheck, unit, integration (testcontainers), e2e (Playwright) на каждом PR; деплой на main.

## 8. Чего сознательно не берём

| Не берём | Почему |
|---|---|
| Микросервисы, Kafka, Kubernetes | Избыточно для прототипа, проверяющий оценивает удобство и надёжность |
| Полноценную регистрацию с паролем | Не требуется заданием и добавляет трение перед первым файлом. Вместо неё сессия + ключ доступа (05-architecture, раздел 6) |
| Хранение только в браузере | Проваливает R7 в реальных условиях (02, раздел 4) |
| GraphQL | 12 эндпоинтов, REST + OpenAPI проще для тестов и агентов |
