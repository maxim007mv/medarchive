## ADR-001. Серверное хранение вместо хранения в браузере

- **Область:** Стек
- **Выбрано:** PostgreSQL + Object Storage на сервере
- **Где:** Все данные архива
- **Отброшено:** IndexedDB / OPFS в браузере
- **Почему:** Хранилище браузера best-effort: браузер вправе очистить его при нехватке места, а пользователь теряет архив при смене устройства; требование R7 «данные сохраняются» не выполняется гарантированно
- **Источник:** S12

## ADR-002. Бэкенд FastAPI на Python 3.12

- **Область:** Стек
- **Выбрано:** FastAPI + Pydantic 2 + SQLAlchemy 2 async
- **Где:** `api/`
- **Отброшено:** Go (chi), Node (NestJS), только Next.js Route Handlers
- **Почему:** OpenAPI 3.1 и JSON Schema генерируются из типов, валидация Pydantic, DI для сессий и скоупов, cookie-сессии из Starlette; Python даёт pypdf и SDK моделей для AI-подсказки. Go быстрее в CPU, но узкое место сеть и S3
- **Источник:** S50

## ADR-003. Фронтенд Next.js 15 App Router + TypeScript

- **Область:** Стек
- **Выбрано:** Next.js, SSR каркаса списка
- **Где:** `web/`
- **Отброшено:** Vite SPA, SvelteKit
- **Почему:** SSR даёт быстрый первый экран; `next/font/local` самохостит Medeo без внешних запросов и сдвига вёрстки
- **Источник:** S54

## ADR-004. Примитивы интерфейса Radix через shadcn/ui

- **Область:** Стек
- **Выбрано:** Radix Dialog, RadioGroup, Popover, Toast
- **Где:** Модалки, сегменты, меню
- **Отброшено:** Свои компоненты, MUI
- **Почему:** Фокус-ловушка, Esc, возврат фокуса на триггер и паттерн WAI-ARIA готовы; стили полностью наши
- **Источник:** S53

## ADR-005. Серверное состояние TanStack Query

- **Область:** Стек
- **Выбрано:** Кэш запросов, оптимистичное обновление заметки с откатом
- **Где:** `web/lib/api`
- **Отброшено:** Redux, SWR
- **Почему:** Снимок в onMutate и откат в onError из документации: заметка не теряется при ошибке
- **Источник:** S56

## ADR-006. Шрифт Medeo Sans и Medeo Mono

- **Область:** Стек
- **Выбрано:** Medeo 1.1.0, OFL 1.1
- **Где:** Весь интерфейс, даты и ключ моноширинным
- **Отброшено:** Inter, системный шрифт
- **Почему:** Открытая лицензия, полная кириллица, вариативная ось веса, моно-начертание для дат; проверено встраиванием в PDF брендбука
- **Источник:** S15
- **Статус:** версия и способ поставки заменены ADR-043; семейство и лицензия действуют

## ADR-007. Хостинг только Yandex Cloud ru-central1

- **Область:** Инфраструктура
- **Выбрано:** Managed PostgreSQL, Object Storage, KMS, Lockbox
- **Где:** Онлайн-среда
- **Отброшено:** Vercel, Fly.io, Neon, Supabase
- **Почему:** Медицинские данные это специальная категория ПДн; хранение ПДн граждан РФ в базах на территории РФ
- **Источник:** S41, S42
- **Статус:** для сдачи прототипа заменено ADR-040; для онлайн-среды с реальными пользователями действует

## ADR-008. Уровень защищённости проектируем как УЗ-2

- **Область:** Безопасность
- **Выбрано:** Меры для специальной категории при угрозах 3 типа и больше 100 тыс. субъектов
- **Где:** Все меры 08-security
- **Отброшено:** УЗ-3 (меньше 100 тыс. субъектов)
- **Почему:** Рост пользователей не должен требовать переделки архитектуры
- **Источник:** S43

## ADR-009. Сессия BFF в cookie вместо JWT в браузере

- **Область:** Безопасность
- **Выбрано:** `__Host-ma_sid`, HttpOnly, Secure, SameSite=Lax, хэш в БД
- **Где:** Веб-клиент
- **Отброшено:** JWT в localStorage, JWT + refresh в браузере
- **Почему:** Токен недоступен XSS, отзыв мгновенный; BFF рекомендован черновиком IETF для браузерных приложений
- **Источник:** S28, S30, S31

## ADR-010. Ключ доступа вместо регистрации

- **Область:** Безопасность
- **Выбрано:** 24 символа Crockford Base32, секрет Argon2id m=19 MiB t=2 p=1
- **Где:** Восстановление архива на другом устройстве
- **Отброшено:** Email + пароль, magic link
- **Почему:** Нет лишних ПДн (email) и внешней рассылки; параметры Argon2id по минимуму OWASP
- **Источник:** S51

## ADR-011. Envelope-шифрование на уровне приложения

- **Область:** Безопасность
- **Выбрано:** DEK на пространство (Tink), обёрнут KEK в Yandex KMS; поля AES-256-GCM с AAD = document_id; файлы Tink Streaming AEAD
- **Где:** Название, заметка, имя файла, PDF
- **Отброшено:** Только шифрование диска провайдером, pgcrypto
- **Почему:** Дамп, бэкап или реплика без KMS не раскрывают данные; pgcrypto передаёт ключ в SQL и журналы; AAD не даёт перенести шифртекст между записями
- **Источник:** S35, S44, S52
- **Статус:** для прототипа «KEK в Yandex KMS» заменено ADR-041 (KEK в файле Tink); параметры шифрования и хранение ключей заменены ADR-047; envelope-схема и AAD действуют

## ADR-012. Криптоудаление при удалении архива

- **Область:** Безопасность
- **Выбрано:** Удаление DEK пространства в KMS + физическая очистка за 24 ч
- **Где:** `DELETE /workspace`
- **Отброшено:** Только удаление строк
- **Почему:** Копии в бэкапах PITR 7 дней становятся нерасшифровываемыми сразу
- **Источник:** S44, S48
- **Статус:** способ заменён ADR-041: в прототипе криптоудаление стирает обёрнутые ключи пространства в БД, а не ключ в KMS

## ADR-013. Изоляция RLS в БД дополнительно к проверкам в коде

- **Область:** Безопасность
- **Выбрано:** FORCE RLS, `app.workspace_id` через `set_config(..., true)`
- **Где:** Все таблицы данных
- **Отброшено:** Только `WHERE workspace_id` в репозитории
- **Почему:** Ошибка в одном запросе не открывает чужие данные (API1 BOLA); локальная настройка безопасна в пуле транзакций
- **Источник:** S27, S32
- **Статус:** дополнено ADR-044 (функции записи для таблиц без доступа `ma_app`)

## ADR-014. PostgreSQL 17+ (проверено на 18)

- **Область:** БД
- **Выбрано:** Managed PostgreSQL 17, совместимо с 18
- **Где:** БД
- **Отброшено:** SQLite, MongoDB
- **Почему:** RLS, GIN, частичные индексы, PITR в управляемом сервисе
- **Источник:** S32, S33, S36

## ADR-015. UUIDv7 как первичный ключ

- **Область:** БД
- **Выбрано:** Генерация в приложении, на PG 18 `uuidv7()`
- **Где:** Все сущности
- **Отброшено:** bigint identity, UUIDv4
- **Почему:** Не раскрывает количество, не перебирается, монотонен по времени: меньше разрывов страниц btree, чем у v4
- **Источник:** S38

## ADR-016. Слепой триграммный индекс для поиска по зашифрованному названию

- **Область:** БД
- **Выбрано:** HMAC-SHA256 триграмм с ключом пространства, `bigint[]`, GIN
- **Где:** `documents.title_bidx`
- **Отброшено:** pg_trgm по открытому тексту, поиск после расшифровки всего архива
- **Почему:** Поиск по подстроке без открытого текста в БД; утечка ограничена частотами триграмм внутри одного пространства (документирована в 07-database)
- **Источник:** S33
- **Статус:** дополнено ADR-046 (правила триграмм документа и запроса, план Q4)

## ADR-017. Keyset-пагинация по сгенерированному ключу

- **Область:** БД
- **Выбрано:** `list_key`, индекс `(workspace_id, list_key, uploaded_at, id)`
- **Где:** Список документов
- **Отброшено:** OFFSET, курсор по смешанным направлениям сортировки
- **Почему:** Стоимость O(page_size) на любой глубине; один направленный ключ даёт условие индекса без Sort
- **Источник:** S21, S39

## ADR-018. Мягкое удаление + очистка за 24 ч

- **Область:** БД
- **Выбрано:** `deleted_at`, ограничивающая политика `hide_deleted`
- **Где:** Документы, архивы
- **Отброшено:** Немедленное физическое удаление, корзина на 30 дней
- **Почему:** Атомарный быстрый ответ пользователю и гарантированное уничтожение по сроку; корзина противоречит ожиданию «удалено без возможности восстановления»
- **Источник:** S34, S48

## ADR-019. Журнал аудита только на добавление, по месяцам

- **Область:** БД
- **Выбрано:** `audit_log`, только имена изменённых полей
- **Где:** Все изменения
- **Отброшено:** Логи приложения
- **Почему:** Подотчётность (STRIDE Repudiation) без копирования ПДн в журнал
- **Источник:** S49, S55

## ADR-020. REST, версия в пути `/api/v1`

- **Область:** API
- **Выбрано:** Ресурсы во множественном числе
- **Где:** Все маршруты
- **Отброшено:** GraphQL, версия в заголовке
- **Почему:** Простое кэширование, логирование и контрактные тесты; версия видна в логах
- **Источник:** S23, S25, S26

## ADR-021. Ошибки RFC 9457 с каталогом кодов

- **Область:** API
- **Выбрано:** `application/problem+json`, `code`, `errors[].pointer`, `title` на русском
- **Где:** Все 4xx и 5xx
- **Отброшено:** Своя обёртка
- **Почему:** Стандарт, стабильный `code` для кода и готовый текст для интерфейса
- **Источник:** S16

## ADR-022. Idempotency-Key на создающих POST

- **Область:** API
- **Выбрано:** 24 часа, отпечаток тела, 400 / 422 / 409
- **Где:** Архив, загрузка, документ, экспорт, подсказка
- **Отброшено:** Без ключа, дедупликация по содержимому
- **Почему:** Двойной клик и повтор после обрыва не создают дубликат
- **Источник:** S19
- **Статус:** дополнено ADR-045 (список операций, хранение тела ответа, отдельная таблица для `POST /workspaces`)

## ADR-023. ETag / If-Match для изменения и удаления

- **Область:** API
- **Выбрано:** Версия строки, 428 без заголовка, 412 при конфликте
- **Где:** PATCH, DELETE
- **Отброшено:** Последняя запись побеждает
- **Почему:** Правка заметки в двух вкладках не теряет текст
- **Источник:** S17, S18, S24

## ADR-024. Курсорная пагинация, `order_by` по AIP-132

- **Область:** API
- **Выбрано:** Непрозрачный `page_token` AES-GCM, `page_size` до 200
- **Где:** `GET /documents`
- **Отброшено:** offset/limit
- **Почему:** Стабильно при вставках, токен нельзя подделать
- **Источник:** S21, S22

## ADR-025. Presigned POST для загрузки

- **Область:** API
- **Выбрано:** `content-length-range` 1 до 20 МБ, бакет карантина
- **Где:** `POST /uploads`
- **Отброшено:** Multipart через API
- **Почему:** API не держит 20 МБ в памяти, лимит проверяет хранилище
- **Источник:** S45, S47

## ADR-026. Лимиты с заголовками RateLimit и 429 + Retry-After

- **Область:** API
- **Выбрано:** GCRA в Redis
- **Где:** Все изменяющие маршруты, вход по ключу
- **Отброшено:** Без лимитов, лимит только на прокси
- **Почему:** Защита от перебора ключа и расхода ресурсов (API4), клиент знает, когда повторить
- **Источник:** S18, S20, S27

## ADR-027. Вебхуков нет в v1

- **Область:** API
- **Отброшено:** Вебхук «документ добавлен»
- **Почему:** Нет потребителей; каждый исходящий вызов это канал утечки и SSRF
- **Источник:** S27

## ADR-028. `Cache-Control: no-store` на ПДн

- **Область:** API
- **Где:** Все ответы с документами
- **Отброшено:** private, max-age
- **Почему:** Копия в кэше на общем компьютере это утечка
- **Источник:** S17, S28

## ADR-029. Модульный монолит + отдельный воркер

- **Область:** Архитектура
- **Выбрано:** `api` (модули documents, uploads, exports, auth, suggestions) + `worker` (arq)
- **Где:** Бэкенд
- **Отброшено:** Микросервисы
- **Почему:** Одна транзакция на создание документа; воркер только для AI и очистки
- **Источник:** S25
- **Статус:** модуль `suggestions` и задачи AI в воркере отложены ADR-042; модульный монолит и воркер очистки действуют

## ADR-030. Ограниченная очередь к модели с отказом 429

- **Область:** Архитектура
- **Выбрано:** 20 задач на инстанс, таймаут 8 с
- **Где:** AI-подсказка
- **Отброшено:** Неограниченная очередь, синхронный вызов без лимита
- **Почему:** Всплеск не превращается в таймауты у всех; основной сценарий не зависит от AI
- **Источник:** S18, S20
- **Статус:** отложено ADR-042 до волны 7

## ADR-031. AI только подсказывает и не сохраняет

- **Область:** Архитектура
- **Выбрано:** Подсказка помечена, дата с цитатой из PDF, сохраняет человек
- **Где:** Форма документа
- **Отброшено:** Автосохранение распознанного
- **Почему:** Задание не требует распознавания; ошибка модели не должна попасть в медицинский архив молча

## ADR-041. Локальный KEK в файле Tink, DEK только на время запроса

- **Область:** Безопасность
- **Выбрано:** KEK: keyset Tink AEAD `AES256_GCM` в файле, который монтируется в контейнеры `api` и `worker` только для чтения как секрет Docker (путь из переменной окружения, сам ключ в окружение не попадает); `workspaces.kek_key_id` хранит id ключа в этом keyset. Связка ключей пространства (ADR-047) расшифровывается KEK в начале каждого запроса и живёт в памяти только до конца запроса; кэша открытых ключей нет. Криптоудаление при `DELETE /api/v1/workspace`: в одной транзакции `deleted_at`, `purge_after = now() + 24 ч` и стирание ключевого материала пространства: ключа полей и файлов и ключа слепого индекса (в DDL 0001 это `dek_ciphertext` и `bidx_key_ciphertext`). По ADR-047 оба ключа хранятся одной связкой в `dek_ciphertext`, а `bidx_key_ciphertext` удаляет миграция 0002, поэтому стирание выполняется как `dek_ciphertext = NULL`; 0002 разрешает NULL только у удалённого архива
- **Где:** BE-01 (`/readyz` проверяет чтение файла KEK), BE-04, BE-10, OPS-12, `core/crypto.py`
- **Отброшено:** Yandex KMS (облака в прототипе нет, ADR-040); локальный эмулятор KMS (лишний сервис, а ключ всё равно лежит на том же диске); кэш открытого DEK на 5 минут из `05-architecture.md` (открытый ключ живёт дольше запроса, а удаление архива не гасит ключ, уже лежащий в кэше другого процесса); KEK в переменной окружения (виден в `docker inspect` и дампах окружения процесса)
- **Почему:** S44: открытый DEK расшифровывается только на время операции. Цена отказа от кэша: одна локальная расшифровка AES-GCM связки размером 390 байт на запрос, без сетевого вызова. Честное ограничение: снимок тома PostgreSQL вместе с файлом KEK расшифровывается целиком, включая архивы, удалённые меньше 24 часов назад и ещё не очищенные. Криптоудаление защищает только от копии БД или тома без файла KEK. В облаке это закрывает KMS, где KEK не покидает сервис. Ограничение записывается в README и в `docs/policy.md`
- **Источник:** S44; замер размера связки на Tink 1.16.1 (Python 3.12); план, раздел «Блок 0»
- **Заменяет:** ADR-011 в части «KEK в Yandex KMS» для прототипа; ADR-012 в части «удаление DEK в KMS»

## ADR-044. Запись в таблицы входа и очереди очистки через функции `SECURITY DEFINER`

- **Область:** БД
- **Выбрано:** Миграция `0002` после `0001_init` (DDL `07-data-model.sql`). Все функции: `SECURITY DEFINER`, владелец `ma_auth`, `SET search_path = pg_catalog, pg_temp`, в теле только полные имена `app.*`, `REVOKE ALL ... FROM PUBLIC`, `GRANT EXECUTE` одной нужной роли. Архив берётся из `app.current_workspace()`, а не из параметра (кроме выборки для воркера). Для `ma_app`: `app.create_workspace(...)` (строки `workspaces` и `consents` для `id = app.current_workspace()`), `app.create_session(...)`, `app.touch_session(...)` (продление простоя, не дальше абсолютного срока), `app.revoke_sessions(...)` (текущая сессия или все сессии архива), `app.issue_access_key(...)` (отзыв активного ключа и выпуск нового в одной транзакции, возвращает `revoked_previous`), `app.revoke_access_key()`, `app.delete_workspace()` (ADR-041: отметка удаления, стирание ключей, отзыв сессий и ключа, отзыв согласия), `app.enqueue_purge(object_key, reason)` (принимает только ключи объектов текущего архива `ws/{id}/...` и `q/{id}/...`). Для `ma_worker`: `app.workspaces_due_for_purge(limit)` возвращает только id архивов, в которых есть просроченное (удалённые документы старше 24 ч, архивы после `purge_after`, загрузки, экспорты и ключи идемпотентности после `expires_at`); дальше воркер ставит `app.workspace_id` и удаляет под RLS своими грантами. Миграция 0002 переводит на тот же `search_path` и функции `resolve_session`, `find_access_key` из 0001
- **Где:** BE-02, BE-04, BE-05, BE-10, BE-13, DB-02, DB-09
- **Отброшено:** Прямые `INSERT` и `UPDATE` для `ma_app` на `workspaces`, `sessions`, `access_keys`, `purge_queue` (ошибка или инъекция в API получает запись в таблицы входа без проверки архива, T13); `BYPASSRLS` для `ma_worker` (воркер видел бы все архивы целиком); политика «без контекста видно всё» для воркера (тот же эффект)
- **Почему:** Проверено на PostgreSQL 17.8 с DDL пакета: от `ma_app` `INSERT` в `workspaces`, `sessions` и `purge_queue` даёт `permission denied`, то есть `POST /workspaces`, вход по ключу и удаление документа невозможны; `ma_worker` без контекста видит 0 архивов и 0 из 6172 мягко удалённых документов сида, то есть очистка невозможна. Функции с узкими аргументами и закреплённым `search_path` повторяют уже принятый шаблон `resolve_session` и `find_access_key` (07-database, раздел 7); `pg_catalog` первым и `pg_temp` последним не дают подменить встроенные функции и операторы объектами из временной схемы
- **Источник:** S32; 07-database, раздел 7; проверка на PostgreSQL 17.8 с `07-data-model.sql` и `db/seed-load.sql`
- **Дополняет:** ADR-013
- **Реализация (миграция 0002, агент DATABASE, 10.11.2026):** итоговый список функций: для `ma_app` `create_workspace`, `create_session`, `touch_session`, `revoke_sessions`, `issue_access_key`, `revoke_access_key`, `delete_workspace`, `soft_delete_document`, `enqueue_purge`, `claim_workspace_create_key`, `complete_workspace_create_key`, `release_workspace_create_key`; для `ma_worker` `workspaces_due_for_purge`, `purge_expired_workspace_create_keys`, `ensure_audit_partitions` (владелец `ma_owner`, без `BYPASSRLS`); внутренняя `require_workspace` без `EXECUTE` для ролей. `app.soft_delete_document(uuid)` добавлена, потому что RESTRICTIVE-политика `hide_deleted` требует, чтобы новая строка `UPDATE` оставалась видимой, и `UPDATE ... SET deleted_at` от `ma_app` отклоняется. ## ADR-045. Идемпотентность всех создающих POST с сохранённым телом ответа

- **Область:** API
- **Выбрано:** Миграция 0002 расширяет CHECK `idempotency_keys.operation` значениями `uploads.create` и `workspace.rotateKey` (к `documents.create`, `exports.create`, `suggestions.create`) и добавляет колонку `response_body_ct bytea`: тело успешного ответа, зашифрованное AEAD-ключом пространства (ADR-047), AAD = `workspace_id` и ключ идемпотентности. Строка и тело живут 24 часа, их удаляет воркер. Повтор с тем же ключом и тем же телом запроса возвращает сохранённый статус и тело с заголовком `Idempotent-Replayed: true`. Ключ фиксируется только для ответа 2xx; при ответе 4xx или 5xx строка `in_progress` удаляется, и повтор выполняется заново. Для `POST /api/v1/workspaces`, где архива ещё нет, отдельная таблица `workspace_create_keys`: первичный ключ `key_sha256` (SHA-256 ключа идемпотентности), `fingerprint`, `state`, `response_status`, `workspace_id` (FK на `workspaces`, `ON DELETE CASCADE`), `response_body_ct` (тело `{workspace, access_key}`, зашифрованное ключом созданного архива), `expires_at = now() + 24 ч`; доступ только через функции 0002 (ADR-044). Повтор `workspaces.create` возвращает тот же архив и тот же ключ доступа, но выдаёт новую сессию (новые `Set-Cookie` и `csrf_token`): токен первой сессии сервер не хранит, только его хэш
- **Где:** `core/idempotency.py`, BE-04, BE-05, BE-06, BE-09..BE-11, DB-07; операции с параметром `Idempotency-Key` в `openapi.yaml`
- **Отброшено:** Хранить только `resource_id` и собирать ответ заново (для `uploads.create` новая подпись политики даёт другое тело, для `workspace.rotateKey` открытого ключа уже нет, хранится только Argon2id); тело открытым текстом (в ответе `documents.create` есть название, в `rotateKey` и `workspaces.create` ключ доступа); строки `POST /workspaces` в `idempotency_keys` с `workspace_id NULL` (ломает первичный ключ `(workspace_id, key)` и политику RLS); хранить сам ключ идемпотентности `POST /workspaces` открытым (до создания сессии он единственное, что связывает повтор с архивом)
- **Почему:** S19: повтор с тем же ключом возвращает результат первой попытки. Без сохранённого тела повтор `rotateKey` выпустил бы ещё один ключ, а повтор `uploads.create` создал бы вторую строку загрузки. В исходном CHECK операций `uploads.create`, `workspaces.create`, `workspace.rotateKey` нет, хотя в контракте у них обязательный `Idempotency-Key`
- **Источник:** S19; `07-data-model.sql`, таблица 8; `openapi.yaml`
- **Дополняет:** ADR-022
- **Реализация (миграция 0002):** колонки для заголовков ответа нет: `Location` и `ETag` повтора выводятся из сохранённого тела. CHECK `idempotency_keys_body_when_completed` не даёт сохранить тело до завершения

## ADR-046. Поиск по подстроке: триграммы запроса без граничных пробелов

- **Область:** БД
- **Выбрано:** (1) Нормализация названия и запроса одинаковая: `lower()`, затем `ё → е`, схлопывание пробельных символов, trim. (2) Слово: непрерывная последовательность букв и цифр, всё остальное разделитель (как в pg_trgm). (3) Документ: полный набор триграмм как у `show_trgm`, каждое слово дополняется двумя пробелами слева и одним справа. (4) Запрос: триграммы без граничных пробелов на краях запроса: у первого слова нет левого дополнения, у последнего нет правого, слова внутри запроса дополняются как в документе. «анали» даёт `ана`, `нал`, `али` и находит «анализ»; «ий анал» находит «Общий анализ крови». (5) Хэш: HMAC-SHA256 ключом индекса пространства от триграммы в UTF-8, первые 8 байт как знаковое big-endian int64, без повторов. (6) Условие `title_bidx @> :hashes` литеральным массивом, затем приложение расшифровывает кандидатов и проверяет подстроку в нормализованном названии; в страницу и в `matched` входят только прошедшие проверку. (7) Запрос из 1 или 2 непробельных символов даёт 422 `validation_error`, пустой или из одних пробелов означает «без поиска»; 3 непробельных символа всегда дают хотя бы одну триграмму. (8) Q4 под `ma_app`: Bitmap Index Scan по `documents_title_bidx` с `workspace_id` в Index Cond, условие `title_bidx @>` в `Filter`. Это ожидаемый план под RLS, критерий DB-06 меняется под него
- **Где:** BE-07, BE-09 (пересчёт `title_bidx`), BE-11 (фильтр экспорта), DB-06, 07-database, раздел 5
- **Отброшено:** Триграммы запроса с граничными пробелами (как было в 07-database, раздел 5): «анали» даёт `ли ` и `  а`, которых нет у «анализ» в середине строки, поиск находит только целые слова и начала слов (проверено на «Общий анализ крови»); хэширование результата `show_trgm` в БД: для кириллицы он возвращает коды вида `0x9e3680` (pg_trgm сжимает многобайтовые триграммы), а приложение хэширует текст триграммы; явные классы операторов GIN `uuid_ops` и `array_ops` для Q4 (на PostgreSQL 17.8 план не меняется); функция поиска `SECURITY DEFINER` с владельцем `ma_auth` (`@>` уходит в Index Cond, но соединение с `documents` обратно даёт 40,1 мс против 2,7 мс); обёртка оператора с `LEAKPROOF` и свой класс операторов GIN (нужны права суперпользователя, которых нет у `ma_owner` и в управляемом PostgreSQL)
- **Почему:** Функция оператора `@>` для массивов (`arraycontains`) не помечена `LEAKPROOF`, а при `FORCE ROW LEVEL SECURITY` планировщик не переносит такие условия запроса в индекс раньше условий политики. Проверено на PostgreSQL 17.8, 10 000 документов в пространстве: под суперпользователем без RLS `title_bidx @>` стоит в Index Cond, под `ma_app` в Filter; время Q4 под `ma_app` 2,7 мс при бюджете 10 мс (07-database, раздел 4). Финальная проверка подстроки нужна не только против коллизий HMAC: документ со словами «ана нал али» содержит все триграммы запроса «анали», но подстроки «анали» в нём нет
- **Источник:** S32, S33, S37; проверка на PostgreSQL 17.8 с `07-data-model.sql` и `db/seed-load.sql`
- **Дополняет:** ADR-016

## ADR-047. Криптопараметры прототипа

- **Область:** Безопасность
- **Выбрано:** Файлы: Tink Streaming AEAD `AES256_GCM_HKDF_4KB`, AAD = `document_id`. Поля: Tink AEAD `AES256_GCM` с префиксом вывода `RAW`, AAD = `document_id`. Ключи пространства (AEAD для полей, Streaming AEAD для файлов, PRF HMAC-SHA256 для слепого индекса) хранятся одной связкой, зашифрованной KEK, в `workspaces.dek_ciphertext`; колонка `bidx_key_ciphertext` удаляется миграцией 0002. Сессия: простой 30 дней, абсолютный срок 180 дней. CSRF-токен: HMAC-SHA256 серверным ключом от id сессии, без хранения; проверка заголовка `X-CSRF-Token` сравнением в постоянное время. Версионирование бакета `ma-docs` выключено
- **Где:** `core/crypto.py`, BE-04, BE-06, BE-08, OPS-01 (бакеты), 07-database, 08-security-privacy
- **Отброшено:** `AES256_GCM_HKDF_1MB` из 08-security (в Python Tink 1.16.1 расшифровывающий поток не поддерживает `seek`, проверено: `seekable()` = False, поэтому `Range` отдаётся последовательной расшифровкой с пропуском до начала диапазона; сегмент отдаётся только после проверки его тега, так что с сегментом 1 МБ первый байт ответа уходит после расшифровки мегабайта и в памяти держится до 1 МБ на запрос, а с сегментом 4 КБ после 4 КБ; накладные расходы сегментов 4 КБ: 456 байт на файл 100 КБ); префикс вывода `TINK` (5 байт id ключа: шифртекст пустой строки 33 байта и проходит CHECK `octet_length(title_ct) >= 29`, а с `RAW` он ровно 28, и CHECK отсекает пустое название); две обёрнутые колонки (две расшифровки KEK на запрос и две копии, которые надо стереть); абсолютный срок 400 дней из 07-database (дольше, чем нужно для архива без регистрации, S28 требует абсолютный срок); CSRF-токен в таблице (лишняя запись на каждую сессию); версионирование `ma-docs` 7 дней из 07-database (удалённый файл остаётся читаемым ещё 7 дней и противоречит 05-architecture)
- **Почему:** Замеры на Tink 1.16.1: связка из трёх keyset в открытом виде 357 байт, под KEK 390 байт, поэтому CHECK `octet_length(dek_ciphertext) BETWEEN 32 AND 1024` не меняется; шифртекст AEAD `RAW` пустой строки 28 байт, одного байта 29 байт. HMAC от id сессии меняется вместе с сессией и не требует хранилища
- **Источник:** S28, S44, S52; замеры на Tink 1.16.1 (Python 3.12)
- **Заменяет:** ADR-011 в части параметров (`AES256_GCM_HKDF_1MB` в 08-security) и раздельного хранения ключа индекса

## ADR-048. Один origin для браузера через прокси Next.js

- **Область:** Архитектура
- **Выбрано:** Браузер обращается только к `http://localhost:3000`. Next.js `rewrites` проксирует `/api/v1/:path*` в контейнер `api` внутри сети compose. На API CORS не включается. MinIO получает правило CORS только на бакете `ma-quarantine`: метод `POST`, origin `http://localhost:3000` (presigned POST идёт из браузера прямо в хранилище); у `ma-docs` CORS нет, публичного доступа нет. Cookie `__Host-ma_sid` с `Secure` выставляется на `http://localhost`. Если WebKit в Playwright не примет `Secure`-cookie на HTTP, E2E переводится на `https://localhost` через Caddy с локальным сертификатом
- **Где:** OPS-01, BE-14, FE-10, QA-04
- **Отброшено:** Отдельный origin API `localhost:8000` с CORS и `credentials` (вторая политика CORS, которую надо держать в соответствии, API8); отдельный контейнер nginx как прокси (лишний сервис: Next.js уже проксирует)
- **Почему:** 05-architecture, раздел 2 уже требует один домен для web и API: cookie `SameSite=Lax` работает без CORS, CSP проще. Риск с WebKit проверяется первым E2E-тестом блока 3 (TC-002)
- **Источник:** S31; 05-architecture, раздел 2; ADR-009
