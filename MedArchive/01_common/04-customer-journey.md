# 04. Путь пользователя от первого входа до выгрузки

Персона: взрослый человек, который получает анализы и заключения в PDF из разных клиник (почта, мессенджеры, личные кабинеты) и хочет держать их в одном месте, чтобы показать врачу или найти к следующему приёму. Работает на ноутбуке, иногда открывает с телефона.

Главные задачи (JTBD):
1. «Когда мне прислали результат анализа, я хочу сохранить его за 30 секунд, чтобы не искать потом по переписке.»
2. «Когда я иду к врачу, я хочу быстро найти и открыть нужное заключение или выгрузить всё за период.»
3. «Когда врач что-то сказал по документу, я хочу записать это рядом с файлом.»

Обозначения экранов совпадают с фреймами в Figma (D = десктоп, M = мобильный) и с `02_design/screens.md` (ADR-049). Канонические тексты интерфейса с ключами: `docs/texts.md`; при расхождении прав словарь.

## Этап 0. Первый вход

| Шаг | Что видит пользователь | Что делает | Что делает система | Экран |
|---|---|---|---|---|
| 0.1 | Загрузка до 1 с: ничего лишнего, шапка | Ждёт | GET `/api/v1/session`: есть cookie `__Host-ma_sid` = открыть архив; нет = онбординг. Архив создаётся только после согласия и выбора файла (`POST /api/v1/workspaces`) | |
| 0.2 | Онбординг: заголовок «Все медицинские документы в одном месте», 3 шага, блок «Где хранятся документы», зона перетаскивания, чекбокс согласия со ссылкой «Политика обработки персональных данных» и кнопка «Выбрать первый PDF»; до отметки кнопка и зона заблокированы с подписью «Отметьте согласие, чтобы выбрать файл» | Читает 10 секунд, отмечает согласие | Cookie нет или GET `/api/v1/documents` вернул 0, поэтому вместо списка онбординг | D01, M01 |

Почему онбординг = пустое состояние, а не тур из 4 слайдов: подсказки в контексте задачи запоминаются лучше, чем вводный тур, и сразу ведут к действию (02, S3).

Состояния этапа 0:

|---|---|

| Cookie отключены | Баннер «Без cookie архив не сохранится между визитами. Разрешите cookie для этого сайта» и ссылка на инструкцию |

Состояния и ошибки этапа 1:
| Ситуация | Где показываем | Текст | Действие |
|---|---|---|---|
| Файл не PDF | Под строкой файла, красный блок | «Файл не добавлен: это не PDF. Сохраните документ в PDF и попробуйте снова» (`not_pdf`) | «Выбрать другой файл» |
| Больше 20 МБ | То же | «Файл больше 20 МБ. Сожмите PDF или разделите его на части» (`file_too_large`) | «Выбрать другой файл» |
| PDF повреждён | То же | «Не удаётся открыть этот PDF. Возможно, он повреждён» (`pdf_unreadable`) | «Выбрать другой файл» |
| PDF не открывается без пароля | То же | «PDF требует пароль для открытия. Снимите пароль и загрузите снова» (`pdf_encrypted`) | «Выбрать другой файл» |
| Пустое название | Кнопка «Сохранить в архив» заблокирована, рядом подпись «Заполните название, чтобы сохранить»; после попытки сохранить (Enter) ошибка под полем | «Введите название документа» (`title_required`) | Фокус в поле |
| Несуществующая дата (31.02.2026) | Под полем | «Такой даты нет. Проверьте день и месяц» (`date_invalid`) | |
| Дата в будущем | Под полем, ошибка, сохранение заблокировано (сервер отвечает 422) | «Дата документа не может быть позже сегодняшней» (`date_in_future`) | Фокус на дату |
| Не выбран тип | Под сегментом | «Выберите тип документа» (`type_unknown`) | |
| Обрыв сети во время загрузки | В модалке | «Связь прервалась на 62%» и «Введённые данные сохранены в форме. Повторите загрузку, когда появится интернет.» | «Повторить загрузку» |
| Ошибка сервера 5xx | В модалке | «Не получилось выполнить действие. Попробуйте ещё раз через минуту» (`internal`) | «Повторить» |
| Пользователь закрывает модалку с введёнными данными | Вложенное подтверждение | «Закрыть без сохранения? Введённые данные не сохранятся.» | «Продолжить заполнение» / «Закрыть» |
| Документ без даты (06 ЭКГ) | Чекбокс отмечен, поле даты заблокировано | Пояснение: «В списке документ будет помечен “Дата не указана”. В фильтре по дате документа он не участвует, его всегда можно найти по названию.» | | D03 |
| Перетащили несколько файлов | Модалка по очереди | «Файл 1 из 3», кнопки «Сохранить и следующий» | |

| 3.1 | Клик по строке открывает `/documents/{id}`: PDF слева во встроенном просмотрщике, справа панель с описанием | Читает PDF | GET `/api/v1/documents/{id}/content?disposition=inline` (поток с расшифровкой, Range, `no-store`) | D09, M06 |

| 3.4 | Кнопка «Очистить» | Жмёт | Поле очищается, тост «Заметка очищена · Вернуть» 6 с (undo вместо подтверждения, потому что действие обратимо) | |

Состояния этапа 3:
| Состояние | Поведение |
|---|---|
| Заметка не сохранилась | Статус красным «Не сохранилось. Повторить», текст в поле не теряется, копия в `sessionStorage` |
| Ухожу со страницы с несохранённой заметкой | Сохранение по `visibilitychange` и `beforeunload` через `fetch(keepalive)` |

| Документ удалён в другой вкладке | 404: «Документ не найден. Возможно, он удалён» (`not_found`) и кнопка «Вернуться к списку» |

## Этап 4. Удаление

| Шаг | Видит | Делает | Система | Экран |
|---|---|---|---|---|
| 4.1 | «Удалить документ» внизу панели (красный текст) или пункт «Удалить» в меню строки «Ещё» | Жмёт | Открывает диалог | |
| 4.2 | Диалог «Удалить документ?»: «Документ «Заключение терапевта» от 10.04.2026, PDF-файл и заметка будут удалены без возможности восстановления.» Кнопки «Отмена» (в фокусе, Enter не удаляет) и красная «Удалить» | Подтверждает | DELETE `/api/v1/documents/{id}` с `If-Match`: документ сразу скрыт, файл и строка физически удаляются за 24 часа (см. архитектуру) | D11, M07 |
| 4.3 | Возврат к списку, тост «Документ удалён» | | Список обновлён; после перезагрузки документа нет | |

Почему подтверждение, а не undo: удаление стирает файл, это единственное необратимое действие в продукте (02, S2). Остальные действия (очистить заметку, сбросить фильтр) обратимы и подтверждения не требуют.

## Этап 5. Экспорт

| Шаг | Видит | Делает | Система | Экран |
|---|---|---|---|---|
| 5.1 | Кнопка «Экспорт» в шапке, всегда видна | Жмёт | | |
| 5.2 | Диалог «Выгрузить документы»: радио «Весь архив · 6 документов», «Только найденные · 2 документа» (активно, если есть фильтр, и выбрано по умолчанию), «Выбранные» (активно, если отмечены строки). Блок «Что будет в ZIP» | Выбирает объём | Размер считается заранее (`total_bytes` ответа `POST /api/v1/exports`) и пишется на кнопке «Скачать ZIP · 157 КБ» (2 найденных документа: 79 114 + 78 110 байт) | D12, M08 |
| 5.3 | Скачивание начинается | | `POST /api/v1/exports` фиксирует состав, затем GET `content_url`: потоковый ZIP | |

Состав ZIP:
```
medarchive_2026-11-10.zip
├── documents/
│   ├── 2026-05-22_uzi-pochek-i-mochevogo-puzyrya.pdf
│   ├── 2026-04-08_obshchiy-analiz-krovi.pdf
│   └── bez-daty_ekg-pokoya.pdf
├── documents.csv     (UTF-8 с BOM, разделитель «;», открывается в Excel)
└── documents.json    (машиночитаемая копия)
```
Колонки CSV: `title; type; document_date; uploaded_at; note; file_name; size_bytes; sha256`. Имена PDF: `{YYYY-MM-DD|bez-daty}_{транслит названия}.pdf`, правила транслитерации в `docs/texts.md`, раздел 13. Файла `README.txt` в архиве нет: состав объясняет блок «Что будет в ZIP» в диалоге.

Пустой выбор: кнопка заблокирована, под ней «Отметьте документы в списке». Ошибка: «Не получилось собрать архив. Попробуйте ещё раз» + «Повторить».

## Этап 6. Повторный визит и другое устройство

| Сценарий | Поведение |
|---|---|
| Тот же браузер, через неделю | Cookie на месте, сразу список |
| Другой браузер или устройство | Онбординг показывает ссылку «Уже есть архив? Открыть по ключу» |
| Ключ доступа | В меню «Хранение и доступ»: ключ из 6 групп по 4 символа, кнопки «Скопировать» и «Скачать как файл». Текст: «Ключ открывает ваш архив на любом устройстве. Храните его как пароль. Мы не сможем восстановить его, если вы его потеряете.» |
| Удалить весь архив | Там же, опасная зона: подтверждение вводом слова «удалить», регистр не важен (02, S2, правило для особо опасных операций). Удаление архива отзывает согласие |
